# Plan Mode가 있는데 왜 MCP Sequential Thinking 이 필요할까?

최근 AI 툴을 사용하다 보면 **이미 AI가 계획(Plan)을 잘 짜는데, 왜 굳이 MCP로 Sequential Thinking과 Context를 연결할까?**라는 의문이 생기기 마련입니다. 
그 차이점을 정리합니다.

### 1️⃣ Sequential Thinking: '상상'과 '실행'의 차이

**Sequential Thinking**은 단순히 단계별로 생각하는 것을 넘어, 각 단계마다 **외부 도구와 상호작용하며 결과값을 확인**하는 과정입니다.

* **Plan Mode (내적 사고):** AI가 가진 지식만으로 "이렇게 하면 되겠지?"라고 머릿속으로 시뮬레이션하는 것입니다. 마치 요리사가 머릿속으로 레시피를 떠올리는 것과 같습니다.
* **MCP Sequential Thinking (외적 절차):** AI가 실제로 **파일을 읽고, 터미널 명령어를 실행하고, 에러를 확인하며** 다음 단계를 결정합니다. 요리사가 실제로 재료를 썰어보고 맛을 보며 다음 양념을 넣는 것과 같은 **'실시간 피드백 기반 사고'**입니다.

> **Key Point:** MCP를 통하면 AI의 사고가 '추측'이 아닌 **'실제 데이터(Fact)'**에 뿌리를 두게 됩니다.

- - -

### 2️⃣ Context Management: '내 방'과 '세상'의 연결

AI 코딩 툴은 이미 내 프로젝트 파일(Local Context)을 잘 이해합니다. 하지만 **Context7** 수준의 고도화된 맥락 관리를 MCP에 추가하는 이유는 **외부 세계와의 동기화** 때문입니다.

* **기존 맥락 이해:** 내 컴퓨터 안에 있는 `auth.ts` 파일의 내용을 기억합니다.
* **MCP 기반 Context:** 내 코드뿐만 아니라, **실시간 외부 API 문서, 실시간 DB 인덱스 상태, 최신 라이브러리 업데이트 로그** 등을 내 코드와 똑같은 수준의 맥락으로 끌어옵니다.

즉, 내 방(Local)에만 갇혀 있던 AI의 시야를 **세상 전체(Global)**로 확장하여, 외부 시스템의 변화까지 실시간 맥락으로 파악하게 만드는 것이 MCP Context 관리의 핵심입니다.

- - -

### 3️⃣ Real-world Case: 실무에서의 결정적 차이

**\[상황] 복잡한 결제 API를 연동하는 작업**

* **Plan Mode만 사용 시:** "일반적으로 이 API는 이런 규격이겠지?"라고 추측해서 코드를 짭니다. (런타임 에러 발생 확률 있음)
* **MCP + Sequential Thinking 적용:** 

  * **Step 1:** MCP로 외부 API 최신 Docs를 실시간 조회.
  * **Step 2:** 우리 DB 스키마와 대조(Context 파악).
  * **Step 3:** 실제 테스트 요청을 보내고 응답을 확인.
  * **Step 4:** 검증된 데이터로만 최종 코드 작성.

- - -

**정리하자면** Plan Mode는 AI의 **'능력'**이고, MCP는 그 능력이 발휘될 수 있는 **'무대(데이터 통로)'**입니다. \
이 둘이 결합될 때 비로소 AI는 단순한 비서가 아닌, 진짜 시니어 개발자처럼 움직이게 됩니다.
