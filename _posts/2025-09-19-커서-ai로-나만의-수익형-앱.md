### 1. AI와 함께하는 앱 서비스 기획

> 수익형 앱 서비스의 성공은 명확한 기획에서 시작됩니다. 이 책은 1인 개발자에게도 핵심 문서화가 얼마나 중요한지 강조하며, AI를 활용하여 효율적으로 기획하는 방법을 제시합니다.

#### 1-1. 타깃 이용자 정의 및 아이디어 리서칭

* 타깃 정의: 가상의 사용자(성별, 나이, 직업, 라이프스타일 등)를 구체화하여 앱의 방향성을 잡습니다.
* 경쟁 앱 분석: 시장의 유사 서비스를 분석하여 차별화 포인트를 명확히 합니다.
* 아이디어 리서칭: 구상한 아이디어가 시장성이 있는지 AI의 도움을 받아 폭넓게 조사합니다.

#### 1-2. 프로젝트의 나침반: PRD (Product Requirements Document)

* 1인 개발자에게도 PRD는 필수입니다. 프로젝트의 목표와 요구사항을 명확히 하여 개발 중 방향을 잃지 않게 합니다.
* 필수항목

  1. TL;DR – 한 문단 요약
  2. Problem Statement – 해결하고자 하는 문제 정의
  3. Goals – 비즈니스 목표 / 유저 목표 / Non-Goals
  4. User Stories – 유저 관점의 요구사항
  5. User Experience – 핵심 플로우와 주요 화면 설명
  6. Narrative – 스토리텔링 방식으로 제품 가치를 전달
  7. Success Metrics – 성과를 측정할 지표
  8. Technical Considerations – 기술적 제약 및 고려사항
  9. Milestones & Sequencing – 개발 단계와 우선순위
  10. Open Questions (선택) – 아직 결정되지 않은 부분 정리

##### 칼로리 계산기 앱 PRD 문서를 예시로 만들어 봤습니다.

```markdown
 # PRD 예시 – 간단한 칼로리 계산기 앱  

## TL;DR  
사용자가 하루 섭취한 음식을 직접 입력해 칼로리를 계산하고, 일일 목표 칼로리와 비교할 수 있는 모바일 앱. 단순하고 빠르게 “기록 → 결과 확인” 경험 제공.  

---

## Problem Statement  
많은 사람들이 건강 관리를 위해 칼로리를 기록하고 싶어 하지만, 기존 앱은 복잡한 DB 검색, 광고, 복잡한 UI 때문에 사용성이 떨어진다.  
우리는 **“직접 기재만으로 빠르게 일일 칼로리 합산을 보여주는 초간단 앱”** 을 만든다.  

---

## Goals  

### Business Goals  
- 시장 검증: “초간단 입력 기반 칼로리 계산기”라는 니치 제품의 수요 검증  
- 사용자 리텐션 확보: 매일 1회 이상 입력 → DAU 유지  
- 확장 가능성: 향후 음식 DB 자동 검색/추천 기능으로 확장  

### User Goals  
- **빠른 입력:** 음식명/칼로리 직접 입력 → 바로 합산  
- **즉각적 결과:** 남은 칼로리(목표 대비), 총합 확인  
- **심플한 경험:** 군더더기 없는 UI, 기록 집중  

### Non-Goals  
- 음식 DB 자동 검색  
- 상세 영양소(단백질, 지방, 탄수화물 등) 계산  
- 소셜 공유 기능  

---

## User Stories  
1. 나는 아침에 먹은 음식을 기록하고, 하루 칼로리 합계를 즉시 확인하고 싶다.  
2. 나는 오늘 목표 칼로리를 설정해두고, 남은 칼로리를 바로 보고 싶다.  
3. 나는 어제 기록을 확인하고 싶다.  

---

## User Experience (Step by Step)  
1. **앱 실행 → 홈화면**:  
   - 오늘 날짜, 목표 칼로리, 현재 총합 표시  
   - “음식 추가” 버튼  

2. **음식 추가 플로우**:  
   - 음식명(텍스트), 칼로리(kcal) 숫자 직접 입력  
   - 저장 → 합산 반영  

3. **일일 합계 화면**:  
   - 오늘 섭취 총합  
   - 목표 대비 % / 남은 칼로리 표시  
   - 어제/이전 기록은 날짜 스와이프 or 달력에서 확인 가능  

---

## Narrative (스토리텔링)  
아침에 바쁜 직장인 지현은 출근길에 바나나를 먹었다. 기존 칼로리 앱을 열면 “검색 → 리스트 → 브랜드 선택 → 광고 닫기 → 저장” 과정이 너무 번거롭다.  
우리 앱에서는 “바나나 / 90kcal”만 적고 저장 버튼만 누르면 끝.  
퇴근길에 앱을 열면, 오늘 총 1,450kcal 섭취했고 목표(1,800kcal)까지 350kcal 남았다는 걸 바로 확인할 수 있다.  
**단순함이 곧 사용성**이다.  

---

## Success Metrics  
- 첫 주차 사용자 30% 이상 재사용률 (Day 7 retention)  
- 하루 평균 입력 음식 개수: 3개 이상  
- 입력 → 저장 플로우 평균 5초 이내 완료  

---

## Technical Considerations  
- 모바일 앱 (iOS, Android) → React Native 등 크로스 플랫폼 고려  
- 로컬 저장소 우선 (SQLite or AsyncStorage), 추후 클라우드 싱크 확장 가능  
- 기본 UX 퍼포먼스: 앱 실행 시 2초 이내 홈 진입  

---

## Milestones & Sequencing  
- **Week 1-2:** UX/UI 와이어프레임, 기본 화면 설계  
- **Week 3-4:** 음식 입력/저장/합산 로직 구현  
- **Week 5:** 목표 칼로리 설정 + 이전 기록 조회 기능  
- **Week 6:** QA 및 클로즈드 테스트  
- **Week 7:** 앱스토어 런칭  
```

#### 1-3. LLM 을 통해 유저 플로우/와이어프레임 생성

> 챗GPT 등을 활용해 PRD를 기반으로 앱의 유저 플로우와 기본적인 와이어프레임 초안을 빠르게 도출합니다.

* 홈화면 진입 → 게시물 목록 탐색 → 게시물 제목 클릭 → 상세 화면 이동 → 댓글 확인 및 작성' 등 구체적인 시나리오를 정의
* 이후 AI에게 요청하여 **개발할 기능을 시각화**합니다.

### 2. 맥락 이해시키기

이 책의 핵심은 AI 에디터 Cursor를 활용하여 개발 생산성을 극대화하는 방법입니다. \
AI와의 협업은 \`맥락(Context) 공유\`가 생명입니다.

#### 2-1. AI의 장기 기억 저장소: Notepads

* Notepads는 AI가 프로젝트의 핵심 정보를 장기적으로 기억하고 참조할 수 있는 공간입니다. 
* 디자인 가이드, PRD, 보안 문서 등 프로젝트의 설계 가이드를 이곳에 저장하여 AI의 역할 일관성과 정확성을 높입니다.

#### 2-2. 맥락 전달을 극대화하는 `@` 기호 활용

* Cursor에서 `@` 기호는 AI에게 특정 컨텍스트를 즉시 참조하도록 지시하는 강력한 도구입니다.

| 지시어                     | 참조 대상           | 목적                        |
| ----------------------- | --------------- | ------------------------- |
| `@File, @Folder, @Code` | 특정 파일/폴더, 코드 블록 | 기존 코드/구조를 참고하여 새로운 코드 작성  |
| `@Docs`                 | README, 공식 문서   | 프로젝트의 규칙, 외부 라이브러리 사용법 준수 |
| `@Git, @Past` chats     | 이전 작업 기록, 대화 내용 | 작업 맥락 유지, 반복 설명 불필요       |
| `@Web` 검색               | 실시간 웹 정보        | 최신 라이브러리 사용법, 에러 해결책 확인   |

#### 2-3. AI와 원활한 대화를 위한 프롬프트 작성법

AI의 잠재력을 최대한 끌어내기 위한 프롬프트 작성의 원칙

* **명확하고 구체적**인 질문/지시하기
* **한 번에 한 가지 작업**만 요청하기
* 기대하는 **결과물의 형태나 제약 조건 명시**하기 (예: "클린 아키텍처를 적용해 줘")
* 테스크 목록 작성하여 **단계별로 AI에게 작업 요청**하기
* **예시 제공**하기 (AI가 선호하는 스타일/규칙 파악)
* **피드백** 주고받기 (점진적으로 결과물 개선)

#### 2-4. AI 행동 지침 설정: Cursor Rules

`.cursor/rules` 디렉토리에 규칙을 정의하여 AI의 행동을 제어하고 코드 품질을 일정하게 유지시킬 수 있습니다.

* User Rules (전역 규칙): 모든 프로젝트에 적용되는 규칙. 선호하는 코딩 스타일, 로그 형식, AI 응답 방식(예: 코드 제안 전 장단점 설명 요청) 등을 설정합니다.
* Project Rules (프로젝트 규칙): 특정 프로젝트에만 적용되는 규칙.

  * 팁: `/` -> **Generate Cursor Rules** 를 통해 자동생성을 도와줍니다.
