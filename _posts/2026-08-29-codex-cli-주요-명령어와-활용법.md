# 주요 명령어와 메모 정리

> [공식 명령어 레퍼런스](https://learn.chatgpt.com/docs/developer-commands?surface=cli)를 참고

## 1. 주요 명령어

| 목적 | 명령어 |
| --- | --- |
| 대화형 세션 시작 | `codex` |
| 특정 요청으로 시작 | `codex "요청 내용"` |
| 최신 정보 검색과 함께 시작 | `codex --search "요청 내용"` |
| 비대화형 실행 | `codex exec "요청 내용"` |
| 마지막 세션 재개 | `codex resume --last` |
| 최근 세션을 새 갈래로 복제 | `codex fork --last` |
| 변경 사항 리뷰 | `codex review` |
| 설치·인증·설정 진단 | `codex doctor` |
| CLI 업데이트 | `codex update` |
| 현재 버전의 도움말 | `codex --help` |
| 플러그인 관련 도움말 | `codex plugin --help` |

## 2. 설치와 로그인

```bash
# 공식 설치 스크립트
curl -fsSL https://chatgpt.com/codex/install.sh | sh

# npm
npm install -g @openai/codex

# macOS Homebrew
brew install --cask codex

# 인증
codex login
codex logout
codex --version

# 설치가 이상하거나 인증·Git·터미널·앱 서버 상태를 한 번에 확인
codex doctor
```

## 3. 대화형 Codex 시작하기

> 여러 기능을 제공하지만, `codex`로 시작한 후 대화 중 제어하는 게 편리하다.

```bash
# 기본 실행
cd ~/git/project/codex-test
codex

# 프롬프트와 함께 시작
codex "로그인 버튼 클릭 시 발생하는 404 오류를 수정해줘"

# 이미지를 첨부하면서 실행
codex -i screenshot.png "이 화면의 삭제 버튼을 제거해줘"
```

## 4. 세션을 이어서 쓰는 명령

> 긴 작업은 한 세션에 몰아넣기보다 목적별로 나누는 편이 관리하기 쉽다.

```bash
# 세션 선택 화면 열기
codex resume

# 현재 디렉터리의 가장 최근 대화 재개
codex resume --last

# ID나 이름으로 특정 세션 재개
codex resume SESSION_ID

# 최근 세션을 별도 대화로 복제해 다른 방향을 실험
codex fork --last
```

`resume --last`는 현재 작업 디렉터리의 최근 세션을 찾는다.  
기존 대화는 그대로 두고 다른 방향으로 작업하고 싶을 때만 `fork --last`를 사용한다.

## 5. 비대화형 실행 `codex exec`

`codex exec`는 대화를 이어가기보다 한 번의 요청을 실행하고 결과를 받을 때 쓴다.
- headless 또는 non-interactive 모드와 유사한 개념
- 스크립트나 CI처럼 사람이 계속 지켜보지 않는 작업에 적합
- 별도의 서버 모드나 백그라운드 서비스는 아님

```bash
codex exec "현재 브랜치의 테스트를 실행하고 실패 원인만 요약해줘"
```

## 6. 코드 리뷰 `codex review`

> 구현이 끝나면 커밋 전에 리뷰를 한 번 돌린다. (vscode IDE를 활용하자! 시안성이 좋지 않다.)

```bash
# 커밋하지 않은 변경 사항 리뷰
codex review

# 기준 브랜치와 비교
codex review --base main

# 특정 커밋 리뷰
codex review --commit COMMIT_SHA
```

## 7. 경로와 모델 지정

### 작업 디렉터리 지정 `-C`

현재 위치를 옮기지 않고 다른 프로젝트에서 실행할 때 쓴다.

```bash
codex -C /path/to/project
codex exec -C /path/to/project "빌드 방법을 확인해줘"
```

### 모델 선택 `-m`

현재 계정과 CLI 버전에서 사용할 수 있는 모델만 선택해야 한다.

```bash
codex -m MODEL_NAME
codex exec -m MODEL_NAME "이 작업을 분석해줘"
```

대화 중 모델은 `/model`, 파일 수정과 명령 실행 권한은 `/permissions`에서 바꾸는 것이 간단하다.

## 8. 프로젝트 지침 `AGENTS.md`
> [OpenAI 공식 AGENTS.md 문서](https://learn.chatgpt.com/docs/agent-configuration/agents-md)   
> OpenAI의 Codex는 프로젝트 지침을 `AGENTS.md`에서 읽는다. `CLAUDE.md`와 비슷한 역할.  

프로젝트 전체에 적용할 내용은 루트의 `AGENTS.md`에 적는다.
```text
AGENTS.md                         # 프로젝트 공통 규칙
services/payments/
└── AGENTS.override.md            # 결제 모듈에서만 적용할 규칙
```
- override
  - 특정 폴더에서만 다른 규칙을 적용하려면 그 폴더에 `AGENTS.override.md`를 만든다.
  - 같은 폴더에 `AGENTS.override.md`와 `AGENTS.md`가 함께 있으면 `AGENTS.override.md`가 우선한다. 
  - 하위 폴더의 지침은 상위 폴더보다 나중에 적용되므로 더 구체적인 규칙을 덧붙이거나 재정의할 수 있다.
- 범위
  - 개인 작업 규칙을 모든 프로젝트에 적용하려면 `~/.codex/AGENTS.md`를 사용한다.  
  - 잠시 다른 규칙을 적용할 때는 `~/.codex/AGENTS.override.md`를 만들고, 작업이 끝나면 이름을 바꾸거나 삭제하면 된다.

## 9. 대화 중 자주 쓰는 슬래시 명령과 단축키

> Codex 대화창에서 입력

| 명령 | 용도 |
| --- | --- |
| `/help` | 사용 가능한 명령과 도움말 확인 |
| `/status` | 현재 세션·모델·권한 상태 확인 |
| `/permissions` | 파일 수정과 명령 실행 권한 설정 |
| `/model` | 모델과 추론 수준 변경 |
| `/review` | 현재 변경 사항 리뷰 |
| `/mcp` | 연결된 MCP 도구 확인 |
| `/init` | `AGENTS.md` 초안 생성 |
| `/exit` | 세션 종료 |

- `Ctrl+R`은 이전 프롬프트를 검색해 다시 불러올 수 있고, `Ctrl+C`는 세션 종료에 사용한다.

## 10. Skills, MCP, Plugins

> 반복해서 쓰는 개발 절차는 Skill, 여러 기능을 묶은 확장은 Plugin, 외부 서버와 직접 연결하는 도구는 MCP로 관리한다.

```bash
# MCP 실재 연결상태
codex mcp
# MCP 목록
codex mcp list

# 플러그인
codex plugin list
codex plugin add plugin-name@marketplace-name
codex plugin remove plugin-name@marketplace-name

codex plugin marketplace list
codex plugin marketplace add <marketplace>
codex plugin marketplace upgrade
codex plugin marketplace remove <marketplace>
```

## 11. 문제 상황별 빠른 진단표

| 증상 | 먼저 실행할 명령 | 확인할 것 |
| --- | --- | --- |
| 명령이 없다고 나옴 | `which codex`, `codex --version` | PATH와 설치 상태 |
| 로그인·인증 문제 | `codex login`, `codex doctor` | 계정, API 키, 만료된 인증 |
| 설정 오류 | `codex --help`, `codex doctor` | 현재 버전이 지원하는 `config.toml` 필드 |
| 파일을 수정하지 못함 | `/permissions` | 작업공간과 권한 범위 |
| 이전 대화가 안 보임 | `codex resume` | 세션 선택 화면 |
| MCP 도구가 안 보임 | `codex mcp list`, `/mcp` | 서버 실행과 인증 상태 |
| 변경이 불안함 | `git diff`, `codex review` | 실제 diff와 회귀 위험 |
