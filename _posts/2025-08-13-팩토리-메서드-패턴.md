> 팩토리 메서드 패턴은 객체를 생성하는 공통적인 방법은 정의하되, 실제 어떤 객체를 만들지는 서브클래스에서 결정하도록 하는 디자인 패턴입니다. 이는 객체 생성 로직을 캡슐화하여, 코드의 유연성과 확장성을 높이는 데 도움을 줍니다.
>
> 이 패턴은 새로운 객체가 생겨도 기존 코드를 변경하지 않아도 되고, 코드를 더 깔끔하게 유지보수할 수 있게 합니다. 또한, 동일한 인터페이스로 다양한 객체를 생성할 수 있게 해줍니다.

### 구조 및 주요 구성 요소

팩토리 메서드 패턴의 핵심 역할은 다음과 같습니다.

* **Product** (제품): 만들어질 객체들의 공통 인터페이스입니다.
* **Concrete Product** (구체적인 제품): 실제 만들어질 객체들을 의미합니다.
* **Creator** (창조자): 객체를 만드는 역할을 하는 클래스로, 추상 클래스나 인터페이스로 정의됩니다.
* **Concrete Creator** (구체적인 창조자): 실제 어떤 객체를 만들지 결정하는 클래스입니다.

### 예시: 햄버거 가게

햄버거 가게를 예로 들면, 주문을 받는 사람(Creator)은 정해져 있지만, 메뉴(Concrete Product)에 따라 불고기 버거를 만드는 주방장, 치즈 버거를 만드는 주방장(Concrete Creator)이 다르게 만드는 상황으로 비유할 수 있습니다. \
햄버거를 만드는 방법은 다르지만, 주문을 받는 방식은 같습니다.

```java
// 1. 햄버거 인터페이스 (Product)
public interface Hamburger {
    void prepare();
}

// 2. 햄버거 종류 (Concrete Product)
public class BulgogiBurger implements Hamburger {
    @Override
    public void prepare() {
        System.out.println("불고기버거 준비 중!");
    }
}

public class CheeseBurger implements Hamburger {
    @Override
    public void prepare() {
        System.out.println("치즈버거 준비 중!");
    }
}

// 3. 햄버거 가게 (Creator)
public abstract class HamburgerStore {
    // 팩토리 메서드
    public abstract Hamburger createHamburger(String type);

    public Hamburger orderHamburger(String type) {
        Hamburger burger = createHamburger(type);
        burger.prepare();
        return burger;
    }
}

// 4. 구체적인 가게 (Concrete Creator)
public class SimpleHamburgerStore extends HamburgerStore {
    @Override
    public Hamburger createHamburger(String type) {
        if (type.equals("bulgogi")) {
            return new BulgogiBurger();
        } else if (type.equals("cheese")) {
            return new CheeseBurger();
        } else {
            throw new IllegalArgumentException("없는 메뉴예요!");
        }
    }
}

// 5. 사용 예시
public class Main {
    public static void main(String[] args) {
        HamburgerStore store = new SimpleHamburgerStore();
        store.orderHamburger("bulgogi"); // "불고기버거 준비 중!" 출력
        System.out.println("---");
        store.orderHamburger("cheese"); // "치즈버거 준비 중!" 출력
    }
}
```

### 팩토리 메서드 vs 템플릿 메서드

두 패턴은 종종 혼동되지만, 목적과 제어 흐름에서 명확한 차이가 있습니다.

| **구분** | **Factory Method**                      | **Template Method**                     |
| ------ | --------------------------------------- | --------------------------------------- |
| 목적     | 어떤 객체를 만들지 하위 클래스에 맡기기                  | 전체 작업 흐름을 고정하고, 일부 단계만 하위 클래스에서 구현하게 하기 |
| 중심로직   | 객체 생성 자체를 위임                            | 전체 알고리즘(순서)을 틀로 정함                      |
| 핵심차이   | 객체를 만드는 방식(createProduct())을 하위 클래스가 바꿈 | 알고리즘의 일부 단계(hook 메서드)를 하위 클래스가 바꿈       |

- - -

### 쉽게 구분 해보기

* **Factory Method**: 어떤 걸 만들지는 네가 정해, 만드는 순서는 몰라
* **Template Method**: 만드는 순서는 내가 정함, 세부는 네가 정해
