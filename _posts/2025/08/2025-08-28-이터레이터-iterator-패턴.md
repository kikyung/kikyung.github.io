## 왜 사용할까?

### 문제 상황:

```java
var 재생목록 = List(Music.of("음악1", "댄스"), Music.of("음악2", "발라드") .....;
```

* 만약 최신 음악 10곡을 먼저 재생하고, 그다음에는 사용자가 가장 많이 들은 곡 5곡을 랜덤으로 재생
* 특정 장르만 재생하고자 할때? 그외 List 만으로 해결이 안될때

### List 만으로 해결하려고 할 경우

1. **캡슐화 위반**: 재생 목록의 내부 구조가 외부에 노출되어, 내부 구현이 변경되면 코드를 사용하는 모든 곳을 수정해야 합니다.
2. **유연성 부족**: 여러 가지 순회 방식(예: 순방향, 역방향, 랜덤)을 추가할 때마다 재생 목록 클래스에 새로운 메서드를 계속 추가해야 합니다.
3. **단일 책임 원칙 위반**: 재생 목록 객체가 `데이터 관리`와 `순회 로직`이라는 두 가지 역할을 모두 떠안게 됩니다.

### 2. 패턴 미적용시

* for 문에 의지하고 요구사항에 유연하게 대응하기 어렵다

```java
public class Main {
    public static void main(String[] args) {
	List<Music> musics = List.of(new Music("음악1")
		                   , new Music("음악2")
		                   , new Music("음악3"));
        for (Music music : musics) {
            System.out.println("재생중 > " + music.getTitle());
        }
    }
}
```

### 3. 패턴 적용시 (순차재생과 랜덤재생 예시)

* 랜덤 이터레이터 클래스 만들기

```java
import java.util.Collections;
import java.util.List;
import java.util.ArrayList;
import java.util.Iterator;

public class RandomIterator implements Iterator<Music> {
    private List<Music> shuffledList;
    private int position = 0;

    public RandomIterator(List<Music> musics) {
        // 원본 리스트를 복사하여 섞습니다.
        this.shuffledList = new ArrayList<>(musics);
        Collections.shuffle(this.shuffledList);
    }

    @Override
    public boolean hasNext() {
        return position < shuffledList.size();
    }

    @Override
    public Music next() {
        if (!hasNext()) {
            throw new java.util.NoSuchElementException();
        }
        return shuffledList.get(position++);
    }
}
```

* 재생 목록 클래스

```java
import java.util.ArrayList;
import java.util.Iterator;

public class Playlist implements Iterable<Music> {
    private ArrayList<Music> musics = new ArrayList<>();

    public void addMusic(Music music) {
        musics.add(music);
    }

    // 기본 순차 재생 이터레이터
    @Override
    public Iterator<Music> iterator() {
        return musics.iterator();
    }

    // 랜덤 재생 이터레이터
    public Iterator<Music> randomIterator() {
        return new RandomIterator(this.musics);
    }
}
```

* 실행(순차 ... 랜덤)

```java
public class Main {
    public static void main(String[] args) {
        Playlist playlist = new Playlist();
        playlist.addMusic(new Music("음악1"));
        playlist.addMusic(new Music("음악2"));
        playlist.addMusic(new Music("음악3"));
        playlist.addMusic(new Music("음악4"));

        System.out.println("=== 순차 재생 ===");
        for (Music music : playlist) {
            System.out.println("순차 재생 > " + music.getTitle());
        }

        System.out.println("\n=== 랜덤 재생 ===");
        Iterator<Music> randomIterator = playlist.randomIterator();
        while (randomIterator.hasNext()) {
            System.out.println("랜덤 재생 > " + randomIterator.next().getTitle());
        }
    }
}
```

## 마무리

> 이터레이터 패턴의 핵심은 이처럼 객체의 순회 로직을 별도의 클래스로 분리하는 데 있습니다. \
> 이를 통해 재생 목록 클래스는 오직 음악 관리라는 본연의 역할에만 집중할 수 있고, \
> 우리는 필요에 따라 새로운 이터레이터 클래스를 만들어 다양한 순회 방식을 유연하게 추가할 수 있게 됩니다.
