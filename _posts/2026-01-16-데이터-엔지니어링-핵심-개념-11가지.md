# 데이터 엔지니어링 핵심 개념 11가지

데이터 시스템을 설계하고 운영하다 보면 반복적으로 마주치는 핵심 개념들이 있습니다. 이 개념들을 제대로 이해하면 시스템의 동작 원리를 파악하고 문제를 예방할 수 있습니다. 실무에서 자주 접하게 될 11가지 핵심 용어를 정리했습니다.

---

## 1. 신뢰성 (Reliability)

**시스템이 예상치 못한 상황에서도 제 기능을 하는 능력**

하드웨어 고장, 소프트웨어 버그, 사람의 실수가 발생해도 시스템이 정상적으로 작동해야 합니다. 이를 '결함 내성(Fault Tolerance)'이라고 부릅니다.

- **왜 중요한가요?** 신뢰성이 낮으면 서비스가 중단되거나 데이터가 손상됩니다
- **실무 예시**: 데이터베이스 서버 한 대가 다운되어도 서비스는 계속 운영되어야 합니다

---

## 2. 확장성 (Scalability)

**데이터와 트래픽이 늘어나도 감당할 수 있는 능력**

사용자가 10명에서 100만 명으로 늘어날 때, 시스템이 그 증가를 합리적으로 처리할 수 있어야 합니다.

- **실무 함정**: 트위터처럼 팔로워가 수백만인 계정(린치핀 객체)이 있다면, 팬아웃 방식으로 모든 팔로워에게 알림을 보내는 것은 비효율적입니다
- **핵심 질문**: "데이터가 10배 늘어나면 어떻게 대응할 것인가?"

---

## 3. 트랜잭션과 원자성 (Transactions & Atomicity)

**여러 작업을 하나로 묶어 모두 성공하거나 모두 실패하게 만드는 것**

계좌이체를 생각해보세요. A 계좌에서 돈이 빠져나가고 B 계좌에 들어가는 두 작업은 반드시 함께 성공하거나 함께 실패해야 합니다.

- **ACID 원칙**: 원자성(Atomicity), 일관성(Consistency), 격리성(Isolation), 지속성(Durability)
- **실패 사례**: 원자성 보장이 없으면 돈은 빠져나갔는데 입금은 안 되는 상황 발생
- **경주 조건(Race Condition)**: 두 프로세스가 동시에 같은 데이터를 수정하려 할 때 발생하는 문제

---

## 4. 복제와 클러스터링 (Replication & Clustering)

**데이터를 여러 서버에 복사해두는 기술**

같은 데이터를 여러 노드에 복사해두면 한 서버가 죽어도 다른 서버가 처리할 수 있습니다.

- **단일 장애점(SPOF) 제거**: Single Point of Failure를 없애는 것이 목표
- **동기 vs 비동기**:
  - 동기 복제: 모든 복사본에 쓰기 완료 후 응답 (안전하지만 느림)
  - 비동기 복제: 일단 한 곳에만 쓰고 응답 (빠르지만 데이터 유실 가능)

---

## 5. 파티셔닝 (Partitioning)

**거대한 데이터를 여러 조각으로 나누어 분산 저장**

테이블을 샤드(Shard)라는 작은 조각으로 나누어 여러 서버에 저장하면 병렬 처리가 가능해집니다.

- **핫스팟 문제**: 특정 파티션에만 요청이 몰리면(데이터 편중, Skew) 병목이 발생합니다
- **활용 사례**: Kafka의 토픽 파티션, MongoDB의 샤딩
- **파티션 키 선택이 핵심**: 어떤 기준으로 데이터를 나눌지가 성능을 결정합니다

---

## 6. 멱등성 (Idempotence)

**같은 작업을 여러 번 해도 결과는 한 번 한 것과 같음**

네트워크가 불안정해서 요청이 중복 전송될 수 있습니다. 이때 멱등성이 보장되면 안전합니다.

- **실무 예시**: 결제 API를 두 번 호출해도 한 번만 결제되어야 함
- **Exactly-once 처리**: Elasticsearch의 upsert 연산처럼 중복 제거를 보장
- **구현 방법**: 요청마다 고유 ID를 부여하고 이미 처리된 ID는 무시

---

## 7. 합의와 선형성 (Consensus & Linearizability)

**분산 시스템에서 모든 노드가 같은 상태를 유지하게 만드는 것**

여러 서버가 "누가 리더인가?"에 동의해야 합니다. 의견이 갈리면 스플릿 브레인(Split-brain) 상황이 발생합니다.

- **선형성**: 시스템이 마치 데이터 복사본이 하나만 있는 것처럼 동작
- **활용 사례**: 
  - 리더 선출 (Raft, Paxos 알고리즘)
  - 분산 락(Distributed Lock)
  - 유일성 제약 조건 보장
- **주의**: 선형성을 보장하면 성능이 떨어질 수 있음

---

## 8. 스트림 처리 (Stream Processing)

**끝없이 들어오는 데이터를 실시간으로 처리**

로그 파일, 센서 데이터, 클릭 이벤트처럼 계속 생성되는 데이터(Unbounded Data)를 다룹니다.

- **배치 vs 스트림**:
  - 배치: 정해진 데이터를 한 번에 처리 (일일 집계)
  - 스트림: 들어오는 데이터를 계속 처리 (실시간 대시보드)
- **시간 윈도우**: "최근 5분간의 평균"처럼 시간 구간을 나누어 처리
- **도구**: Apache Kafka, Apache Flink, Spark Streaming

---

## 9. ETL과 변경 데이터 캡처 (ETL & CDC)

**데이터를 추출하고 변환해서 옮기는 파이프라인**

- **ETL**: Extract(추출) → Transform(변환) → Load(적재)
- **CDC**: 데이터베이스의 변경 사항만 감지해서 동기화

**이중 쓰기 문제**: 애플리케이션이 데이터베이스와 검색 엔진에 동시에 쓸 때, 한쪽만 성공하면 불일치 발생

- **해결책**: CDC를 사용해 데이터베이스의 변경 로그를 읽어서 검색 엔진에 반영
- **도구**: Apache NiFi, Airflow, Debezium

---

## 10. 로그 구조 저장소 (Log-structured Storage)

**데이터를 추가만 하는 로그 파일 형태로 저장**

기존 데이터를 수정하지 않고 계속 뒤에 추가만 합니다(Append-only).

- **LSM 트리**: Cassandra, HBase, RocksDB에서 사용
- **장점**: 쓰기가 매우 빠름
- **단점**: 
  - 주기적으로 컴팩션(Compaction) 필요 → CPU/디스크 사용량 급증
  - 테일 레이턴시(Tail Latency) 증가 가능

---

## 11. 데이터 스테이징 (Data Staging)

**데이터를 최종 목적지에 넣기 전 임시로 검증하는 단계**

데이터 웨어하우스에 바로 넣지 않고, 중간 영역에서 데이터 품질을 먼저 확인합니다.

- **왜 필요한가요?**
  - 잘못된 데이터가 웨어하우스를 오염시키는 것 방지
  - 원천 시스템에 부하를 주지 않고 검증 수행
- **검증 항목**: NULL 체크, 중복 제거, 형식 검증, 범위 확인
- **도구**: Great Expectations, dbt의 테스트 기능

---

## 마무리

이 11가지 개념은 데이터 시스템을 설계할 때 반드시 고려해야 할 요소들입니다. 각 개념이 독립적이지 않고 서로 연결되어 있다는 점을 기억하세요.

- 신뢰성을 높이려면 복제가 필요하고
- 확장성을 위해서는 파티셔닝이 필요하며
- 실시간 처리를 위해서는 스트림 처리와 멱등성이 중요합니다

실무에서 문제를 만났을 때, 이 개념들을 떠올리며 "어떤 원칙이 지켜지지 않았나?"를 생각하면 해결의 실마리를 찾을 수 있습니다.
