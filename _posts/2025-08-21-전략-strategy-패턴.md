# 할인 계산 적용 사례

> 숙박 프로모션 할인가 계산에 적용한 **전략 패턴(Strategy Pattern)**을 소개해 드리겠습니다.\
> 할인 타입이 퍼센트 할인, 원 할인, 할인 없음 등으로 나뉘어 있고, 
> 각각의 할인 계산 로직이 다를 때 어떻게 설계하면 좋을까요?



## 문제 상황

숙박업 프로모션 시스템에서 다음과 같은 할인 타입들을 지원해야 합니다:

* **퍼센트 할인**: 가격의 일정 비율만큼 할인
* **원 할인**: 고정 금액만큼 할인  
* **할인 없음**: 할인 적용하지 않음

만약 전략 패턴 없이 구현한다면 다음과 같은 코드가 나올 수 있습니다:

```java
public int calculateDiscount(AccomPromotion promotion, int price) {
    if (promotion.getDiscountType() == PercentOrWon.PERCENT) {
        return (int) (price * promotion.getDiscountValue() / 100.0);
    } else if (promotion.getDiscountType() == PercentOrWon.WON) {
        return promotion.getDiscountValue();
    } else {
        return 0;
    }
}
```

이 방식의 문제점은 무엇일까요?

* 새로운 할인 타입이 추가될 때마다 `if-else` 문을 수정해야 함
* 할인 계산 로직이 복잡해질수록 메서드가 길어짐
* 각 할인 타입별로 테스트하기 어려움

## 전략 패턴으로 해결

### 1. 전략 인터페이스 정의

먼저 할인 계산을 위한 전략 인터페이스를 정의

```java
public interface PromotionDiscountStrategy {
    int calculateDiscount(AccomPromotion promotion, int price);
}
```

### 2. 구체적인 전략 클래스 구현

```java
// 퍼센트 할인 전략
public class PercentDiscountStrategy implements PromotionDiscountStrategy {
    @Override
    public int calculateDiscount(AccomPromotion promotion, int price) {
        return (int) (price * promotion.getDiscountValue() / 100.0);
    }
}

// 원 할인 전략  
public class WonDiscountStrategy implements PromotionDiscountStrategy {
    @Override
    public int calculateDiscount(AccomPromotion promotion, int price) {
        return promotion.getDiscountValue();
    }
}

// 할인 없음 전략
public class NoDiscountStrategy implements PromotionDiscountStrategy {
    @Override
    public int calculateDiscount(AccomPromotion promotion, int price) {
        return 0;
    }
}
```

### 3. 전략 선택 / 사용

```java
private PromotionDiscountStrategy toDiscountStrategy(AccomPromotion accomPromotion) {
    if (accomPromotion.getDiscountType() == PercentOrWon.PERCENT) {
        return new PercentDiscountStrategy();
    } else if (accomPromotion.getDiscountType() == PercentOrWon.WON) {
        return new WonDiscountStrategy();
    }
    return new NoDiscountStrategy();
}

// 할인 계산 시 전략 사용
int discountAmount = toDiscountStrategy(promo).calculateDiscount(promo, discountedPrice);
```

## 전략 패턴의 장점

### 1. **확장성 (Extensibility)**

새로운 할인 타입이 필요할 때 기존 코드를 수정하지 않고 새로운 전략 클래스만 추가하면 됩니다.

```java
// 새로운 할인 전략 추가 예시
public class BuyOneGetOneStrategy implements PromotionDiscountStrategy {
    @Override
    public int calculateDiscount(AccomPromotion promotion, int price) {
        // 1+1 할인 로직 구현
        return price / 2;
    }
}
```

### 2. **유지보수성 (Maintainability)**

각 할인 전략의 로직이 독립적으로 관리되어 수정이 용이합니다.

### 3. **테스트 용이성 (Testability)**

각 전략을 독립적으로 테스트할 수 있습니다.

```java
@Test
void percentDiscountStrategy_shouldCalculateCorrectDiscount() {
    // given
    PromotionDiscountStrategy strategy = new PercentDiscountStrategy();
    AccomPromotion promotion = createPromotion(PercentOrWon.PERCENT, 20); // 20% 할인
    
    // when
    int discount = strategy.calculateDiscount(promotion, 10000);
    
    // then
    assertThat(discount).isEqualTo(2000);
}
```

### 4. **단일 책임 원칙 (Single Responsibility Principle)**

각 전략 클래스는 하나의 할인 계산 책임만 가집니다.



## 마무리

전략 패턴을 통해 할인 계산 로직을 유연하고 확장 가능하게 설계할 수 있었습니다. 
이 패턴은 비슷한 알고리즘들이 여러 개 존재하고, 
**런타임에 적절한 알고리즘을 선택해야 하는 상황에서 매우 유용**합니다.

특히 비즈니스 로직이 복잡해지고 다양한 정책을 지원해야 하는 
커머스 시스템에서는 전략 패턴을 잘 활용해 볼수 있을것 같습니다.
